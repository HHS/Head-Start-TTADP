# Figma Code Connect (frontend)

This directory holds [Figma Code Connect](https://developers.figma.com/docs/code-connect/)
mappings that link components in the **TTA Hub Design Library** Figma file to the
real React components we ship. When a mapping is published, a developer inspecting
that component in Figma Dev Mode sees our actual code snippet instead of generic
autogenerated markup.

Mappings are validated locally with `yarn figma:parse` and published to Figma
automatically by CI when they change on `main` — see "Publishing" below.

## Layout

- `frontend/figma.config.json` — Code Connect config (`codeConnect` block: include
  globs, `label`, `language`).
- `frontend/src/codeConnect/*.figma.ts` — one template file per mapped component.
- `frontend/package.json` scripts:
  - `yarn figma:parse` — validate mappings locally. **No Figma token needed.**
  - `yarn figma:publish` — publish mappings to Figma. **Requires a token; do not run casually.**

`src/codeConnect` is excluded from the app `tsconfig.json`: template files
import a virtual `figma` module and are only ever executed by the Figma CLI, so
they must not be typechecked or bundled into the app.

## Format: v2 template files

We use `@figma/code-connect@^2`, which uses **template files** (`.figma.ts`).
Figma removed the older framework-specific parser (`.figma.tsx` +
`figma.connect(Component, url, {...})`) and **stopped maintaining it on
2026-08-17**, so we author templates directly — no parser.

A template file is plain TypeScript that reads the selected Figma instance and
returns the snippet to show. See the
[template file docs](https://developers.figma.com/docs/code-connect/template-files/).

## Adding a mapping

1. In Figma, open the component and "Copy link to selection" (URL must contain a `node-id`).
2. Create `src/codeConnect/<Component>.figma.ts`.
3. Start with the header comment block, then read instance props and return the snippet:

   ```ts
   // url=<figma-url-with-node-id>
   // component=Button

   import figma from "figma"

   const variant = figma.selectedInstance.getEnum("State", {
     Primary: "button",
     Secondary: "outline",
   })

   export default {
     id: "Button",
     imports: ["import { Button } from '@trussworks/react-uswds';"],
     example: figma.code`<Button${figma.helpers.react.renderProp("type", variant)}>Label</Button>`,
     metadata: { nestable: true },
   }
   ```

   - `figma.selectedInstance.getEnum/getString/getBoolean(...)` reads Figma props.
   - Wrap the snippet in `figma.code`; use `figma.helpers.react.renderProp` for
     correct JSX prop rendering (handles quoting/booleans). For a value you know
     the exact shape of, you can inline it instead, e.g. `count={${count}}`.
4. Prefer Figma variables/tokens over hardcoded values (`get_variable_defs` via the
   Figma MCP server). Map to `@trussworks/react-uswds` components and USWDS utility
   classes — never author new CSS (`best_practices.md`).
5. Validate: `yarn figma:parse`. Fix until it parses cleanly.
6. Record the Figma `node-id` and the date you read the design in a file comment —
   designs change and nothing notifies you.

Tip: to convert an old `.figma.tsx` parser file, run `yarn figma connect migrate`
and then simplify the generated template.

## The Alert pilot & its known gaps

`Alert.figma.ts` maps the design library **Alert** set (`node-id 1786:15733`)
to the trussworks `Alert`. Only the `State` variant is mapped (→ `type`). Two
Figma variants have **no 1:1 code equivalent** and are intentionally left
unmapped — resolve as `[NEEDS DECISION]` with design before mapping:
- `Type=List` — trussworks `Alert` has no list variant; a list is just markup
  passed as `children`.
- `Type=Dismissable` — trussworks `Alert` has no native dismiss control.

## Homepage mapping

`HomePageLink.figma.ts` maps the Actionable Notifications file's Widget
(`720:57116`) to the reusable homepage card. It reads the title, description,
and action label from text descendants. Navigation targets, icon definitions,
and same-tab external-link behavior are application-owned inputs; the example
accepts those typed values rather than assigning every widget the same URL.

On 2026-09-21, Figma suggested an additional Widget (`1275:67878`), Icons
(`1:11`), and Button (`38:3571`), but its context API could not resolve those
source IDs. Their mappings remain a follow-up requiring valid source component
links. Local parsing validates template packaging, not execution against live
Figma instances. No mappings are published by `yarn figma:parse`.

## Publishing

Publishing writes the mappings to the Figma file. It is handled by the
`Publish Figma Code Connect` GitHub Actions workflow
(`.github/workflows/figma-code-connect.yml`), which runs:
- on push to `main` when `frontend/src/codeConnect/**` or
  `frontend/figma.config.json` changes, and
- on manual dispatch (Actions tab → "Publish Figma Code Connect" → "Run workflow").

The job runs `figma:parse` first, then `figma:publish`, both with
`--exit-on-unreadable-files` so a broken mapping fails the job instead of being
silently skipped.

### Token setup

The workflow reads the `FIGMA_ACCESS_TOKEN` repository secret. **Never commit a
token.** Either token type below works; switching between them only requires
replacing the secret's value.

Preferred — **plan access token** (not tied to a person; Organization/Enterprise
plans only):
1. A Figma org admin creates a token at <https://www.figma.com/developers/tokens>
   (requires 2FA unless SSO is enforced).
2. Choose the **Figma CLI** token type. The REST API type cannot write Code
   Connect.
3. Set an expiration (max 1 year) and copy the secret — it is shown only once.

Fallback — **personal access token** from a Figma account with a Dev or Full
seat: Figma → Settings → Security → Personal access tokens, with the
**Code Connect: Write** and **File content: Read** scopes.

Then add it to the repo:
1. GitHub → repo Settings → Secrets and variables → Actions → New repository secret.
2. Name: `FIGMA_ACCESS_TOKEN`; value: the token.
3. Run the workflow manually once and confirm the mappings appear in Figma Dev Mode.

Tokens expire. Record the expiry date and owner, and refresh before it lapses —
refreshing a plan access token keeps the old secret valid for 24 hours, so update
the GitHub secret within that window. When replacing a personal token with a plan
token, revoke the personal token in Figma afterward.

### Publishing locally

Rarely needed; prefer the manual workflow run.
1. `export FIGMA_ACCESS_TOKEN=<token>`
2. `yarn figma:publish`
